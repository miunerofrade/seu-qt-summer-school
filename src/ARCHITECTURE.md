# 源码模块说明

- `app`：应用程序外壳，负责主窗口、页面导航和各功能模块的装配。
- `widgets`：不包含业务规则的可复用 Qt 控件与布局。
- `features`：按功能集中存放界面、控制器、业务服务、模型和专用控件。
- `domain`：车站、车次、乘车人、订单、车票和余票等业务实体。
- `data`：本地 JSON 数据的读取、保存、异常恢复和默认数据。
功能目录（需要修改一个功能时，先从对应目录查找）：

- `auth`：独立登录/注册窗口、动画、上次成功登录信息预填。
- `query`：车票查询、筛选、排序、席别代理，以及 12306 请求和缓存服务。
- `passengers`：乘车人信息管理。
- `booking`：购票确认、出票和余票扣减。
- `orders`：订单查询、订单详情和退票。
- `admin`：车站、车次、时刻、票价和余票管理。
- `statistics`：售票、退票、收入和余票统计，包含统计模型和两个专用图表。
- `settings`：数据目录、手动保存、重新加载和备份恢复。

## 文件查找与整理边界

- `main.cpp`：创建 QApplication、设置字体和翻译，启动应用控制器和唯一的事件循环。
- `app/applicationcontroller.*`：持有数据和窗口，集中管理延迟初始化、登录切换、退出登录、
  原生登录菜单和窗口销毁；不属于主窗口内部页面。
- `app/mainwindow.ui`：主窗口及各页面的静态布局；本轮保留原布局，不拆 UI。
- `app/mainwindow.cpp`：组装各功能控制器、导航及菜单权限。
- `features/<功能>/*controller.cpp`：页面交互；`*service.cpp`：业务规则；
  `*model.cpp`、`*proxymodel.cpp`、`*delegate.cpp`：表格显示与筛选。
- 公共控件只保留头像、日期输入、对话框样式和流式布局；统计专用图表归统计功能。
- 服务可以被其他功能复用，例如购票调用乘车人服务和铁路查询服务；归档位置表示
  职责归属，不增加新的调用层，也不复制实现。
- 原 `models/`、`services/` 中的代码已归回功能目录；没有保留转发头文件或重复副本。
- 测试保留 `auth_tests` 与 `phase1_tests` 至 `phase6_tests` 名称，避免改变现有测试入口。
  第一轮整理仅修改文件位置、引用路径和说明；未改变 JSON 格式、账号权限、业务规则及启动时序。

## 登录与账号数据

- `ApplicationController` 先显示 `features/auth/LoginDialog`，150ms 后初始化
  `DataStore`。登录成功后先显示忙碌状态，150ms 后创建主窗口；退出登录销毁主窗口及
  控制器，清空当前账号，再显示登录页。登录和注册页均支持系统退出快捷键，macOS 有原生退出菜单。
- JSON 仅支持当前第 4 版，账号字段为 `id`、`username`、明文 `password`、`role`。
  缺少文件时创建 `admin/admin` 和演示乘车人；注册只能创建 `user`。旧版或损坏文件
  明确报错并保持原文件，不再自动迁移或重建。课程演示按要求使用明文密码。
- `DataStore` 保存内存中的当前账号 ID，并提供登录、注册、账号名称和归属判断；不引入
  独立权限框架。管理员构造全部控制器，普通用户保留查询、乘车人、订单、购票及账号设置；
  设置页提供退出登录，数据管理和备份恢复仅管理员可见。
- 乘车人和订单必须保存 `ownerUserId`；默认演示乘车人归 `user-admin`。普通用户的列表、
  详情、购票乘车人及修改入口检查归属；管理员使用同一页面访问全部用户记录。
- 车票、退款经订单确定归属；车次和区间库存始终全局共享。恢复业务备份时保留当前账号
  数组，账号 ID 无法匹配时显示原 ID。
- 登录页的 SVG 圆弧由 Qt 动画驱动旋转，列车图标静止，窗口隐藏后停止动画；需要 Qt Svg。
- 查询页的两个站点框共用只读列表模型，按最小字符宽度计算尺寸；目录未变化时保留模型和
  正在输入的文字。站点目录有效期为 24 小时，需要更新时延后发起请求，车票查询仍实时进行。
  设置环境变量 `QT_SYNC_PROFILE_STARTUP=1` 可在控制台查看初始化各阶段耗时。

## 当前依赖方向

```text
界面 / Controller
       ↓
Model / Proxy Model
       ↓
业务 Service
       ↓
DataStore
       ↓
IDataRepository → JsonRepository
```

Controller 只负责收集输入、显示结果和页面跳转。乘车人校验、基础数据约束、
关联删除检查等规则由 Service 执行；Service 通过 `DataStore` 原子提交并自动保存。
购票的登录、请求字段和乘车人归属校验集中在 `BookingService::validateRequest`；
服务通过引用要求有效的数据仓库。官方车次导入仍按原流程先提交再购票，由于提交会
发出 `dataChanged`，购票前必须重新校验当前状态，不跳过这道业务检查。
除已明确要求的圆角操作按钮等视觉规则外，下拉框、日期框、复选框、表格等优先使用
Qt 原生控件和平台行为，不为原生控件添加额外的 QSS 外观覆盖。

订单详情按单张车票办理退票；手续费、状态更新、退票记录与区间余票恢复均在 Service
中原子完成，保存失败不会替换内存数据。
车站、车次、时刻/经停站、席别/票价/余票分别使用独立管理对话框，正式需求未要求的
维护日志不进入当前实现。

## 铁路数据边界

- `railway-stations.json` 是随程序保存的 12306 站点目录快照，当前为 3384 站；它只读，
  查询页会把它与 `app-data.json` 中启用的自定义站点合并。
- `RailwayQueryService` 只按用户选择的日期和区间查询余票，不抓取全国运行图。查询结果、
  站点目录和已按需取得的经停站分别写入 `railway-cache.json`。
- 12306 官方数据不在管理页修改。管理页只编辑自定义站点、自定义每日车次，以及用于过滤
  官方查询结果的隐藏车次号。
- 当前 12306 网页仍使用 `czxx/queryByTrainNo` 提供单趟列车的有序经停站，但余票接口的
  `data.result` 已由明文竖线字段改为加密内容。解析器检测到这种响应时会明确报接口变化，
  不会把它保存成“零车次”；课程展示可继续使用已有缓存和自定义数据。

## 运行实例与区间库存

- 自定义车次定义不带日期，表示每日重复运行；第一次对某日购票时会复制出该日的库存实例，
  因此不同日期互不扣减。跨日由经停站 `dayOffset` 表示。
- 官方车次使用 `(运行日期, 12306 train_no)` 标识一次运行，公开显示车次号只用于展示。
  同一运行途中即使显示车次号变化，只要内部标识相同，仍共享同一份库存。
- 一个席别对每两个相邻经停站保存一份 `SegmentInventory`。购买 A→D 必须检查并扣减
  A→B、B→C、C→D 的全部区间，查询余票取覆盖区间的最小值；退票反向恢复全部区间。
- 12306 仅返回“有”而没有数量时，本演示以 50 作为本地库存初值。它只用于课程演示，
  不代表真实余票。

公开接口没有稳定的物理车底/列车组 ID，因此本项目只能合并同一 `train_no` 的运行服务；
不能可靠断言两个不同内部标识的车次由同一列车组担当。
